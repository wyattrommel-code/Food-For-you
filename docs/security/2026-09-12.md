# Security changes, September 12, 2026

## Live Supabase

Applied migrations `20260912182546_secure_recipe_access` and `20260912182743_recipe_sources` to project `yhfqlvblqlpacjdkltfi`. They are recorded in Supabase migration history and in this repository. The older, undated SQL files describe earlier schema states; do not replay them on the live project.

- Enabled RLS on recipes with shared reads and authenticated owner-only personal recipe CRUD. A client cannot insert a shared recipe, promote a personal recipe into the catalog, transfer ownership, or edit shared rows.
- Replaced public step-image writes with owner checks against the parent recipe. Private step-image reads follow recipe visibility. Shared images remain readable.
- Limited client table grants to required row operations; removed TRUNCATE, REFERENCES and TRIGGER privileges. Anonymous access is read-only on shared recipes and their step images.
- Tightened profile, preference and favorite policies to the authenticated owner. Favorite creation requires a visible recipe.
- Revoked direct client execution of privileged signup and RLS event-trigger functions. The signup trigger still creates profile and preference rows. Pinned the signup function's search path.
- Added recipe-owner and step-image foreign-key indexes.

`supabase/tests/recipe_security.sql` creates temporary fixtures and two temporary auth users inside a transaction, then rolls everything back. Assertions cover anonymous reads/writes, missing auth claims, cross-account isolation, shared-catalog mutation, owner CRUD, ownership transfer, promotion, step-image relinking, preferences, favorites, trigger privileges and signup behavior. Passed in a rollback dry run and after the live migration. Nine real auth users and the existing private recipe were preserved.

The final Security Advisor has **no database errors or function-execution warnings**. Its remaining warning is [leaked-password protection](https://supabase.com/docs/guides/auth/password-security#password-strength-and-leaked-password-protection), available only on Pro and above. It remains disabled under the user's no-cost constraint. No plan was upgraded. The performance advisor's shared/owner read-policy warning reflects the intentional two-policy read model; its remaining foreign-key indexing advice is separate from security.

## Dependencies

Initial `npm audit --omit=dev`: 40 affected package entries, including two critical. Compatible updates and targeted overrides leave **zero critical, moderate or low entries**. The eight remaining high entries are one image-size dependency and the Expo/Metro packages inheriting its two advisories. The raw audit is saved alongside this note; its counts describe package-version advisories, not eight distinct vulnerabilities or eight verified mobile exploits.

- Updated compatible dependency versions without changing Expo SDK 54 or React Native 0.81.
- Pinned PostCSS 8.5.28 and brace-expansion 1.1.18 for the 1.x branch. Xcode's UUID dependency uses CommonJS-compatible 11.1.1; its consumed `v4` API has a regression check.
- [decode-uri-component 0.5.0](https://github.com/SamVerschueren/decode-uri-component/security/advisories/GHSA-vcc3-ghjq-m6fr) fixes malicious encoded-input decoding. Its upstream export is ESM, while the installed query-string expects a CommonJS function. `vendor/decode-uri-component` contains that MIT-licensed upstream implementation with only the export changed to CommonJS, plus the original license. No decoding algorithm was invented. The npm override resolves to this local package.
- image-size 1.2.1 is a **build-time Metro dependency** here. The [ICNS](https://github.com/advisories/GHSA-w3rx-r6r6-pgpr) and [JXL/HEIF](https://github.com/advisories/GHSA-5p2g-fcmc-qvqq) advisories have no published patched version. `scripts/patch-image-size.cjs` adds minimum-length guards to its ICNS entry reader and box lookup, preventing non-advancing loops. It runs on `postinstall`, is repeatable, and fails on an unexpected package version or source shape. Zero-size boxes are rejected. Keep the guards until a reviewed upstream fix replaces them.

The image-size package version is deliberately unchanged, so npm still reports its advisories. Do not claim an audit result of zero. If installing with `--ignore-scripts`, run `node scripts/patch-image-size.cjs` before any build. `npm test` checks malformed ICNS, JXL and HEIF inputs in child processes with timeouts, checks malformed URL input through query-string, and confirms normal PNG/ICNS, Unicode query parameters, PostCSS and Xcode UUID behavior.

This is a targeted remediation of the findings above, not a full penetration test or a claim that every application feature is production-ready. No APK/AAB was uploaded or production release submitted.

## Credential follow-up requiring account access

A hardcoded Spoonacular API key was found in the legacy `seed-spoonacular.js`, already tracked in Git history at commit `08c25cf`. Its value has been removed from the working tree and key-fragment logging deleted. The old script now requires an explicitly supplied environment variable; the free recipe workflow does not use it. No Spoonacular API request was made and no paid quota was consumed.

**Revocation is still required if the old key remains active.** The [Spoonacular account console](https://spoonacular.com/food-api/console) is signed out in the available browser, so revocation could not be verified or performed. The account owner must sign in and revoke/regenerate the exposed key. Removing a value from the current file does not remove it from existing Git history or revoke it. History was not rewritten.
