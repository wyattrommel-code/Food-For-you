# Weekly planner, sweet treats, and smoothies

The home screen's smaller **I need a sweet treat** button sits below **I'm Hungry Now**. Hungry Now excludes every recipe tagged dessert, including mixed breakfast/dessert recipes, at all three time fallbacks. Treats returns distinct hot, cold, and quick/easy choices from the preference-filtered catalog. Serving temperatures are explicitly reviewed; a baked dessert that is served chilled is not automatically labeled hot. Missing categories show an honest empty state rather than duplicate or incorrectly labeled recipes. Quick/easy means at most 15 minutes and effort 1–2.

**Smoothies & Shakes** is available from Home, category browsing and Create. Its add shortcut preselects the category without clearing a recipe draft. Browsing includes shared recipes and the current account's private smoothies/shakes, with existing preference filtering. There are currently no shared smoothies/shakes in the catalog; this change adds the category and authoring flow, not new recipes.

**Weekly planner** opens its own screen from Home or **Add to planner** on any recipe. Users choose a local calendar day and Breakfast, Lunch, Dinner, Snack, Dessert, Smoothie / shake, or Day's menu. Multiple recipes can be stored under the same meal. Users can search the shared catalog and their private recipes, navigate between weeks, reopen planned recipes, move them, and remove them. Adding the same recipe twice to the same day/meal is idempotent. Moving onto an existing identical item reports the conflict. Saved plans are personal to the signed-in account and available across its devices; household sharing is not enabled for plans in this version.

Plans save in Supabase `public.meal_plans`. RLS enforces ownership for all operations, rejects ownership reassignment and private-recipe references belonging to another user, and grants no anonymous access. The user/date/meal/recipe unique index supports weekly queries. Dates are local `YYYY-MM-DD` values, avoiding UTC day shifts and daylight-saving arithmetic errors. Saves require a connection; errors keep the selected recipe ready to retry. No offline-save promise is shown.

Verification: 97 unit tests and TypeScript checking passed. The rollback-only database test exercises owner CRUD, moving, other-account isolation, private-recipe protection, and anonymous grants. Browser QA exercises Hungry Now dessert exclusion, three distinct treat picks, small/normal/landscape layouts, the smoothie Create shortcut, planner save/reload/move/remove, and failed-save retry. Existing security-advisor findings are unchanged: deliberately locked internal household tables and account-level leaked-password protection disabled; no planner findings were reported.

The database migration is applied. These app UI changes require a new Android testing build before they appear in the Google Play installation. No paid build or subscription was started for this change.
